# 08 — Audit Design

## Two streams, both immutable
1. **`core.audit_events`** — business audit: who did what to which object.
   Columns: `id, occurred_at, org_id, actor_user_id, actor_roles[], action, object_type, object_id, object_ref, before JSONB, after JSONB, trace_id, ip, user_agent`.
2. **`core.security_audit_events`** — security stream: failed webhook signatures (ADR-005), authz denials, privileged actions (bank change approvals, payout freeze/unfreeze, role grants), MFA events, rate-limit trips.
   Columns: `id, occurred_at, org_id NULL, actor_user_id NULL, event_type, severity, detail JSONB, trace_id, ip`.

## Immutability enforcement (defense in depth)
- `BEFORE UPDATE OR DELETE … RAISE EXCEPTION` trigger on both tables (and all IMM domain tables: bids, results, settlements, kyc_records, custody_events, qc_results, temperature_excursion_events, order_status_history, market_price_snapshots, bank_accounts).
- App DB role granted `INSERT, SELECT` only on IMM tables.
- Partition-ready (monthly, by `occurred_at`) — Build 0 keeps single tables; partitioning is a later operational task (recorded as tech debt).

## Write path
- `AuditWriter` (common/audit) writes in the **same transaction** as the mutation it audits (no lost audits on rollback).
- Actor/org/trace pulled from `RequestContext` (AsyncLocalStorage) — no manual plumbing in services.
- Privileged actions are double-recorded: business audit + security audit.

## Correlation
`trace_id` (W3C traceparent-compatible, generated by trace-ID middleware, propagated to outbox events, queue jobs, webhook handlers, and audit rows) makes every mutation reconstructable end-to-end.

## Query policy
Audit reads are admin-only (`audit.read` permission), paginated by cursor, filterable by org/actor/object/time. No update/delete API exists.

## Baseline test (acceptance gate)
Perform a seeded mutation → assert one `audit_events` row with matching actor/object/trace_id, and assert UPDATE on the audit table raises (immutability trigger).
